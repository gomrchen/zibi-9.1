新手必看的 DNS 解析设置方法-域名解析教程[新手教程]

来源：https://www.zibll.com/48922.html · 离线镜像

搭建一个 WordPress 网站，第一步就是先把域名和服务器购买好，那么购买好了之后，我们需要做的就是域名解析了。这篇教程就教大家一步一步、正确地做好域名解析。

DNS 解析会告诉浏览器：这域名应该去访问哪一台服务器。

本文会用 zibll.com 和 www.zibll.com 作为示例，带你了解域名解析的基本概念、常见记录类型，以及阿里云、腾讯云 DNSPod、Cloudflare 等常见服务商的设置流程。

需要准备什么

在开始解析之前，你需要准备好以下信息：

  1. 一个已经注册好的域名，例如 zibll.com
  2. 一台网站服务器，例如云服务器、虚拟主机、宝塔面板服务器等
  3. 服务器的公网 IP 地址，例如：192.0.2.123

如果你的网站使用的是 CDN、对象存储、SaaS 建站平台，服务商可能会提供一个 CNAME 地址，例如：

example.cdn-provider.com

这种情况下就不是填写 IP，而是添加 CNAME 记录。

常见的几种解析记录

1. A 记录

A 记录用于把域名指向一个 IPv4 地址，是网站解析中最常见的方式。

示例：

含义是：zibll.com -> 192.0.2.123 www.zibll.com -> 192.0.2.123

2. CNAME 记录

CNAME 记录用于把一个域名指向另一个域名，常见于 CDN、云存储、企业邮箱、托管平台。

示例：

含义是：www.zibll.com -> cname.example.com

注意：CNAME 的记录值必须是域名，不能填写 IP 地址。

3. MX 记录

MX 记录用于邮箱收信。如果你只是搭建网站，暂时可以不用配置 MX 记录。

4. TXT 记录

TXT 记录常用于域名验证，例如 SSL 证书验证、邮箱 SPF 验证、站长平台验证等。

阿里云解析示例

登录阿里云均值台：进入云解析 DNS，选择目标域名，进入解析设置，然后点击添加记录。阿里云也说明了，主域名使用 @，www.example.com 这类域名主机记录填写 www。

操作步骤：

  1. 登录阿里云控制台
  2. 进入「云解析 DNS」
  3. 在域名列表中找到 zibll.com
  4. 点击进入「解析设置」
  5. 点击「添加记录」
  6. 添加第一条记录：记录类型：A 主机记录：@ 解析线路：默认 记录值：192.0.2.123 TTL：默认或 10 分钟
  1. 再添加第二条记录：记录类型：A 主机记录：www 解析线路：默认 记录值：192.0.2.123 TTL：默认或 10 分钟
  1. 保存后等待解析生效

参考：阿里云官方文档 添加解析记录

腾讯云 DNSPod 解析示例

进入云解析 DNS 控制台，添加或选择域名，进入记录管理，然后添加解析记录。腾讯云的新手快速解析也会为网站添加 www 和 @ 两条 A 记录。

操作步骤：

  1. 登录腾讯云控制台
  2. 进入「云解析 DNS」
  3. 如果域名不在列表中，点击「添加域名」，输入：zibll.com
  4. 点击域名进入「记录管理」
  5. 点击「添加记录」
  6. 添加主域名解析：主机记录：@ 记录类型：A 线路类型：默认 记录值：192.0.2.123 TTL：默认
  7. 添加 www 解析：主机记录：www 记录类型：A 线路类型：默认 记录值：192.0.2.123 TTL：默认
  8. 保存记录，等待解析生效

参考：腾讯云官方文档 快速添加域名解析

Cloudflare 解析示例

Cloudflare 的操作逻辑稍有不同。你需要先把域名添加到 Cloudflare，然后按照 Cloudflare 提供的 NS 服务器地址，到域名注册商处修改 DNS 服务器。之后，解析记录就需要在 Cloudflare 中管理。

操作步骤：

  1. 登录 Cloudflare
  2. 添加站点：
  3. zibll.com
  4. 选择套餐
  5. Cloudflare 会扫描已有 DNS 记录
  6. 进入「DNS」或「Records」页面
  7. 点击「Add record」
  8. 添加主域名 A 记录：

Type：A Name：@ IPv4 address：192.0.2.123 Proxy status：按需求选择 TTL：Auto

添加 www A 记录：

Type：A Name：www IPv4 address：192.0.2.123 Proxy status：按需求选择 TTL：Auto

  1. 保存记录

Cloudflare 有一个特别容易让新手困惑的选项：Proxy status。

  • 开启代理：流量会经过 Cloudflare，通常显示橙色云朵
  • 仅 DNS：只做 DNS 解析，不经过 Cloudflare，通常显示灰色云朵

如果你只是想先让域名正常指向服务器，可以先选择「DNS only」。等网站正常访问后，再根据需要开启 Cloudflare 代理、缓存、防护等功能。

参考：Cloudflare 官方文档 Manage DNS records

域名解析后多久生效

解析记录保存后，并不是所有地区都会立刻生效。常见情况如下：

如果你刚刚修改过 DNS 服务器，不同地区、不同网络看到的结果可能不一致，这是正常现象。

检查解析是否生效

你可以使用以下方式检查：

方法一：浏览器访问

直接访问：

http://zibll.com http://www.zibll.com

如果服务器已经配置好网站，应该可以打开页面。

方法二：使用命令检查

Windows 可以使用：

nslookup zibll.com nslookup www.zibll.com
nslookup zibll.com nslookup www.zibll.com
nslookup zibll.com nslookup www.zibll.com

macOS / Linux 可以使用：

dig zibll.com dig www.zibll.com
dig zibll.com dig www.zibll.com
dig zibll.com dig www.zibll.com

如果返回的 IP 是你的服务器公网 IP，例如：192.0.2.123

说明解析基本已经生效。

常见错误

1. 主机记录填写错误

错误写法：

主机记录：www.zibll.com

推荐写法：

主机记录：www

主域名则填写：

主机记录：@

2. 把 CNAME 记录值写成 IP

CNAME 的记录值应该是域名，不能是 IP。

错误示例：

www CNAME 192.0.2.123

正确示例：

www CNAME example.cdn-provider.com

如果你要指向 IP，应使用 A 记录。

3. 只解析了 www，没有解析主域名

如果只添加了：

www.zibll.com

那么用户访问：

zibll.com

可能打不开。

建议新手同时添加：

@ www

4.解析好了，但网站还是打不开

这不一定是 DNS 问题，还可能是：

  • 服务器没有绑定这个域名
  • WordPress 站点地址配置错误
  • 宝塔、Nginx、Apache 站点未绑定域名
  • 服务器安全组没有放行 80 / 443 端口
  • 网站没有配置 SSL，但强制跳转到了 HTTPS
  • 域名未备案，国内服务器拦截访问
